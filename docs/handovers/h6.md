# Slice H6 — Discovery and signed per-person snapshot

Authorizing issue: **#10** (`CaioFaSoares/Bond`, labels `area:host`, `area:shared`, `epic:E01`, `sp:3`,
`type:story`, milestone "Block 1 — One guild, synced"), assigned by the implementation track
coordinator with gate #1 already closed (`docs/canonico.md` §14: RF-30…RF-55 approved by the owner on
2026-10-16). Same footing H2/H4 recorded for #5/#8: the issue carries no `em-curso` label — that label
does not exist in this repository's vocabulary (`docs/handovers/h2.md`, `c1.md`) — so the authorization
is the milestone plus the coordinator's assignment. The issue's requirements in play are RF-31 (the
pinned key is what later snapshots must verify against), RF-32 (the host boots empty; H4 owns the setup
code) and RF-34 (the org catalog comes from the host).

Contracts followed: `docs/specs/SP04-sync.md` §1 (the `Discovery` document and §1.1's fingerprint:
SHA-256 of the raw public key, first 10 bytes, Crockford base32, `XXXX-XXXX-XXXX-XXXX`) and §2 (the
body, `ETag: "<version>"`, `Bond-Signature: kid=<kid>; sig=<base64url>` over the exact bytes,
`version` = base64url of the first 16 bytes of SHA-256 of the unsigned body, `304` on an
`If-None-Match` hit); `docs/specs/SP03-host-api.md` §1 (the status table, the auth levels, the error
shape — no cookies on an authenticated answer, JSON in and out) and §2 (`GET /.well-known/bond`
public, `GET /v1/state` at the person level); `docs/specs/SP01-host-data-model.md` §1 (the signing key
file and the `kid` = first 16 bytes of SHA-256 of the raw public key, base64url) and §2
(`meta.guild_name`); `docs/specs/SP07-host-deployment.md` §1–§2 (the deployment environment, and the
image that ships `shared/` and `host/` only); `docs/specs/README.md` (base64url without padding, ISO
8601 UTC); `docs/handovers/b1.md` (what the Bond side expects: `Discovery.fingerprint` = the string
`fingerprintOf` computes, `Bond-Signature` exactly `kid=…; sig=…`), read against
`backend/host-client.ts` byte for byte. Rules: `AGENTS.md`, `host/context.md`, `shared/context.md`.

## Decisions and deviations for the coordinator

1. **`version` digests the body with an empty `version`.** SP04 §2 says "SHA-256 of the unsigned
   body", and the body carries its own `version`: a field cannot hash itself. Everything else in the
   document is hashed exactly as it travels, and `host/state.test.ts` pins the formula
   (`snapshotVersion(serializeSnapshot({...body, version: ''})) === body.version`). Read literally the
   sentence is unimplementable; this is the closest reading.
2. **`issuedAt` is the instant the content appeared, not the instant of the response — and that is
   what makes `304` reachable.** `issuedAt` is part of the signed body, so a fresh instant per
   response would give every poll a new `ETag` and SP04 §2's `304` could never happen; the host keeps,
   per person, the digest of the content it issued last, and answers the same instant while the
   content holds. The table is in memory, like SP02 §5's rate limits (`host/context.md`): after a
   restart the next answer re-issues an instant newer than the one the Bond accepted, which SP04 §2
   allows, and the version moves once. **Divergence to confirm**: if the owner prefers `issuedAt` to
   be "now" per response, the price is that `If-None-Match` never hits and the `ETag` becomes
   decorative.
3. **The bytes are deterministic on purpose.** `serializeSnapshot` orders every object's keys and
   keeps arrays in their own order (the catalog, the views and the favorites are ordered data). The
   only free-form value in the document is `Entry.auth` (a JSON column of `repo.ts`), and ordering its
   fields is what keeps a hand-written `{"noFill":true}` from moving the version of an otherwise
   identical state.
4. **The signing key is loaded in `routes/state.ts`, not decorated on the context.** `createApp`
   stays synchronous and `AppDeps` is untouched: `loadOrCreateSigningKey(config.dataDir)` is memoized
   per data dir, one read per process, and `createApp` already reads `host-secret` from the same
   directory the same way (`loadOrCreateHostSecret`, H4's decision 2). H5 offered a `signingKey`
   loader decoration and dropped it after this slice said it would load the pair itself, so
   `host/app.ts` decorates `config`/`db`/`repo`/`auth` only and nothing of H6 widens the app's
   dependencies.
5. **The discovery's `guild` and `minAppVersion` come from the deployment environment of SP07 §2**
   (`BOND_GUILD_NAME`, `BOND_MIN_APP_VERSION`, whose compose default `0.3.0` is applied when unset).
   `HostConfig` carries neither, and `meta.guild_name` — the row SP04 §1 annotates `guild` with
   (SP01 §2) — still has no writer; H2's handover already recorded that gap. Reading `meta` today
   would answer an empty guild on a fresh host, a document the Bond refuses (`readDiscovery` requires
   a non-empty `guild`), so the route reads the value's origin instead and the exact
   `host/config.ts`/`host/main.ts` change is written out under "For other owners". **Divergence to
   confirm**: the moment boot writes `meta.guild_name`, the route should read that row and drop the
   environment read.
6. **`fingerprintOf` is a second implementation, with an equality test.** The host image ships
   `shared/` and `host/` only (`host/Dockerfile`), so `host/` cannot import
   `backend/host-client.ts`; `shared/host-api.ts` keeps its base32 encoder private and is not this
   slice's file (B1's handover raised the same finding). `host/state.test.ts` asserts both
   implementations answer one string for one key, and the real boot asserted the Bond's own
   `discover()` accepts the document. The move into `shared/host-api.ts` stays with the coordinator.
7. **`me` is built field by field.** `HostPerson` carries `activatedAt`/`disabledAt` next to
   `Person`, and a spread would put them on the wire; the test pins `me`'s keys exactly and the
   body is asserted to carry no `salt`, `auth_hash`, `token_hash` or `password`.
8. **The `304` carries the `ETag` and no body**, which RFC 9110 §15.4.5 asks for and
   `backend/host-client.ts` ignores (it reads only the status). `etagMatches` accepts the quoted
   version the Bond sends, a bare version, a `W/` validator, a list and `*`; only an exact version is
   a hit, so a malformed header can never suppress a body the caller needed.
9. **The two answers are raw `Response` objects.** Elysia serializes an object body itself, and the
   signature is over the bytes the route produced: handing the string over as a `Response` body keeps
   the signature and the body the same bytes by construction.
10. **`SnapshotEnvelope` (`shared/host-api.ts`) stays unused on the host side.** The route sets the
    two headers from the `version` and the `SnapshotSignature` it computed; the type describes the
    pair but no host code needs the wrapper. A finding for the contract's owner, not a change here.
11. **`personalViews` and `personalTools[].views` overlap by design.** `repo.listPersonalViews`
    returns every personal view of the person, including the ones under their own personal entries,
    which also travel inside that entry's `views`. SP04 §2 says `personalViews` is "mine, under any
    entry I see", and a person's own personal entry is one they see; the test pins the shape both
    ways.
12. **No new dependency, no toolchain change.** WebCrypto (`Ed25519`, `SHA-256`) and the standard
    library only; the route file names no `bun:*` module.

## What was left out

- **The block 2 members of `Snapshot`** (`people`, `incomingShares`, `holders`, `rotationPending`):
  `shared/host-api.ts` keeps them out until their story lands, and the host follows that type
  exactly.
- **The pin itself (RF-31) and the sign-in (RF-32)** are B1/B2's and H4's; this slice signs the
  document those stories verify and pin.
- **Comparing `minAppVersion`** is not the Bond's behaviour yet (`docs/handovers/b1.md` decision 6
  reads it and does not compare it; O2/O1 owns the comparison). The discovery answers it because
  SP04 §1 requires the field.
- **`meta.guild_name`'s writer** and the two `HostConfig` fields: `host/config.ts` and
  `host/main.ts` are not this slice's files, so the change is written under "For other owners"
  rather than applied.
- **No project gate** and **no measurement of the snapshot at guild scale** (the cost of two digests
  and one signature per poll is `leitura`, not a measurement).

## For other owners

  Add to `HostConfig` and `loadConfig`: `guildName` from `BOND_GUILD_NAME` (trimmed; SP07 §2's
