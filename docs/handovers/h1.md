## Decisions and deviations for the coordinator

1. **`--filter ./host` does not work here (SP07 §1's `[INFERENCE]` resolved as a fallback).** The
   root `package.json` declares no `workspaces`, so the filtered install matches no package and
   installs nothing (measured above). The Dockerfile therefore installs inside `host/` from
   `host/bun.lock` (`host/package.json` is copied into `WORKDIR /app/host`). This keeps the property
   SP07 §1 cares about — only Elysia enters the image — without touching the root `package.json`,
   which is not mine. If the coordinator wants SP07 §1 verbatim, the root `package.json` needs
   `"workspaces": ["host"]` and a single root lockfile: a decision for its owner.
2. **`oven/bun:1.4.3-slim` exists** (SP07 §1's other `[INFERENCE]`), and `1.4.3` matches the version
   `.github/workflows/release.yml` pins.
3. **`migrations.ts` owns the connection and the runner** until `repo.ts` exists. H1's migration 1 is
   `meta` alone; per SP01 §5 a fresh `/data` must report `schema_version = 1` for block 1, so **H2
   appends the block 1 tables to that same entry** (legal while block 1 is unreleased); block 2
   tables become a new entry. `applyMigrations` also refuses a database whose `schema_version` is
   newer than the build (a rolled-back container).
4. **The dev flag is `BOND_DEV=1`** (SP07 §2 names "dev" without naming a variable). The refusal is
   read literally: outside dev even `http://127.0.0.1` is refused. SP04 §1's loopback allowance is
   about the address the Bond accepts, not about the host's own public URL.
5. **`host-secret` is the 32 raw bytes** SP01 §1 names, not base64 — H3/H4 read it as the HMAC key of
   SP02 §4. `signing-key.json` is JSON text as specified.
6. **compose needs `BOND_PUBLIC_URL` for every subcommand** (`${BOND_PUBLIC_URL:?…}`): the variable is
   the address the Bond pins and SP07 §2 forbids assuming one, so there is no default and no silent
   blank. The cost is that `down`, `logs` and `ps` also need it set (or Coolify's stack env).
   `BOND_GUILD_NAME` keeps SP07's literal `${BOND_GUILD_NAME}` and therefore warns when unset; H5/H6
   consume it.
7. **Port publishing is new** (SP07 §2's compose has no `ports`): acceptance item 3 asks for `/health`
   on 8080. It is `${BOND_BIND:-127.0.0.1}:8080:8080` — loopback by default, `BOND_BIND=0.0.0.0` where
   the proxy lives outside the compose network. No host address is written down.
8. **`host/tsconfig.json` is not a working typecheck today**: Bun's globals (`Bun`, `bun:sqlite`,
   `process`) have no ambient types because `@types/bun` would be a second dependency
   (`AGENTS.md` allows only Elysia inside `host/`), and `host/` is outside the repo's `typecheck`
   scripts. Adding a host typecheck gate is a decision for the coordinator.
9. Keys are created without an existence-race guard (`flag: 'wx'`-style): SP01 §1 has one replica and
   one writer, and a locked-volume race is not in this slice.

## What was left out

- No route beyond `GET /health`, no `repo.ts` queries, no `meta.guild_name` / `meta.created_at` rows:
  those belong to H2 (`repo.ts`) and H5 (`/v1/*`).
- No backup timer, rotation or `cli/` scripts (`setup-code`, `backup-now`, `restore`): SP07 §3–§4,
  stories after H1.
- No project gate was run (`bun run typecheck`, the full `bun test test/`, formatters): the mandate
  allows only `bun install` in `host/`, `bun test host/` and the compose cycle, which is what ran.
- Nothing is blocked. Docker was available, so no fallback to a local-only verification was needed.
