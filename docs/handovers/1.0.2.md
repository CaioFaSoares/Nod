# 1.0.2 — gateway, private-network HTTP and a manual release

Owner's request on 2026-11-27: implement the plan for the host gateway (RF-80) and private-network
HTTP for guild tools (RF-81), fix connected saves that dropped tags and the org account, commit, and
release as 1.0.2. GitHub Actions is still blocked by billing, so the release took the manual path of
1.0.1 (`docs/handovers/1.0.1.md`).

## 1. Scope

- `5a0a564` — RF-80 and RF-81 (requirements and decisions in `docs/canonico.md` §14 and §22;
  contracts in SP01, SP03, SP04 and SP07 §7).
- `8af9710` — `backend/host-admin.ts`'s `orgTool` now sends `tags` and `orgAccount`; before it,
  every connected tool save cleared both on the host.
- `59c0a51` — `Release 1.0.2:`, the version in `app.json` and `package.json`; its body is the update
  notice.

## 2. Validation (execution, on `59c0a51`)

`bun run validate`: 4/4 stages, 74.6 s — typechecks (src, backend, host, Electrobun), unit tests of
`test/` and `host/`, desktop and portal builds.

## 3. Manual build and publication

1. **arm64:** `NOD_APP_ID=copland.nod bun run eb:build` with Bun 1.4.4 (arm64).
2. **x86_64:** `bun scripts/build-nod-native.ts --arch=x86_64`, the icon, page bundle and config
   steps with the arm64 Bun, then only `electrobun build --env=stable` under Rosetta with the
   official `bun-darwin-x64` 1.4.4 standing in as `node` on `PATH`. The Electrobun launcher runs
   under `node`, and Hutch builds for the arch it reports. Running the whole `eb:build` under the x64
   Bun fails at vite, because the installed rolldown has no `darwin-x64` binding.
3. **Rebuild arm64:** both builds share `electrobun/native/build/libNodNative.dylib`, so
   `eb:build` ran again for arm64 last.
4. **Checks:** `bun run eb:verify`, `bunx tsc -p electrobun/tsconfig.json --noEmit` and
   `codesign --verify --strict --deep` on both apps. Launcher and payload `libNodNative.dylib` are
   arm64 / x86_64 respectively, both plists say 1.0.2, and both payloads embed `resources/seed.json`.
5. **Packaging:** `scripts/eb-publish.ts` with the `latest/download` base URL and the release
   commit's body. The two manifest halves were merged with the workflow's `jq`, and the app's
   `parseManifest` accepted the result.
6. **Publication:** `gh release create release-1.0.2 … --latest` on `59c0a51`. The two zips were
   downloaded again from the public `latest` URLs, and their SHA-256 matched the manifest.
7. **Cask:** `Casks/nod.rb` regenerated from the published manifest by `scripts/brew-cask.ts`.

## 4. Limits

- **macOS only.** Windows/Linux 1.0.2 do not exist while Actions is blocked.
- **No native UI smoke** was run for this release (`bun run validate --smoke` was not executed).
- **Server acceptance of RF-80/RF-81** is the owner's: SP07 §7 lists the steps. The host image
  changes only when the Coolify deployment is redeployed from `main`.
- **Not run:** an HTTP tool on a private network inside the macOS webview. App Transport Security
  might refuse it — an inference, not an observation.
