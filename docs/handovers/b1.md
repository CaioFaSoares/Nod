## Acceptance criterion — how each item was met

**1. `backend/host-client.ts` verifies `Bond-Signature` with the pinned key over the raw bytes
before parsing.** `leitura` of `backend/host-client.ts:465-475`: `readBody` hands the bytes to
`verify(signatureBytes(sig), bytes, publicKey)` *before* `new TextDecoder().decode(bytes)` and
`parseJson`. `execucao`: *a snapshot the pinned key signed is verified and handed back verbatim*,
*one byte changed after signing fails and hands back nothing* (a single `a`→`b` inside the served
JSON), and *the bytes are verified before they are parsed* — correctly signed non-JSON passes the
signature and fails at the shape check (`invalid`), while valid JSON the pinned key did not sign
fails as `signature`.

**2. A changed host key is refused with `host key changed — remove and add the host again`.**
`execucao` of two routes: a snapshot whose `kid` is another pair's, and a *discovery* of an already
added host answering another key (`discover(origin, { pinned })`). Both raise `HostError` with
`failure === 'key-changed'` and `message === HOST_KEY_CHANGED`, compared against the exported
constant, which is the exact SP04 §1 string. A third test pins the other half: the same `kid`
signing with another key is a `signature` refusal, never an accepted snapshot.

**3. The bearer lives in the keychain under `bond.host.<kid>.<personId>`, never in SQLite or
`store.json`.** `execucao`: `tokenKey()`/`hostTokenKey` are asserted equal to
`bond.host.<kid>.<personId>`; after `saveToken`, `/v1/ping` is called with
`Authorization: Bearer <token>` read from the fake keychain; then **every table of a real SQLite
database** (a `host` row and a `host_outbox` row present) is dumped as text and asserted not to
contain the token, nor the word `Bearer`; `forgetToken` makes the item disappear and the next call
carry no header (→ `signed-out`). For `store.json` the proof is structural and `leitura` of the
module: `HostClientDeps` holds `fetch`, `keychain`, `now`, `timeoutMs` — there is no `store` and no
repo, so there is no path to it (the same argument the acceptance of the file list implies).

**4. Local schema migrates to `user_version = 3` (SP05 §2) without touching local-mode data.**
`leitura` of the DDL against SP05 §2 column by column (same names, same types, same defaults, same
order; the only difference is the `IF NOT EXISTS` this file uses everywhere). `execucao`: a fresh
database is stamped 3 with `host` and `host_outbox`; a v2 database (the SP05 §2 columns dropped, the
two host tables dropped, `PRAGMA user_version = 2`) migrates to 3 with its person (roles included),
tool, vault item (origin included), event and `meta` row unchanged, its new columns at their
defaults (`scope = 'org'`, `owner_id IS NULL`, `password_algorithm = 'PBKDF2-SHA256'`,
`client_id IS NULL`), and a `PRAGMA table_info` equal to a fresh database's for every table.

**5. Without a host, the Bond makes no host call.** The acceptance asks for a network capture, which
is B11's smoke; what B1 owes is the construction, and it holds in two places: `createHostClient`
performs no I/O at all — `execucao` of a test that builds a client and calls `connect(pinned)` with
a counting `fetch` and leaves the counter at 0 — and every network path goes through `discover`
(which needs an address the person typed) or through a `connect` that demands the pinned key, which
`backend/main.ts` can only obtain from `repo.hostRecord()`. `leitura` of the module: the two
`deps.fetch` call sites are inside `send`, which only `discover` and a `HostConnection` reach.

## What could not be done

- **No project gate, no typecheck.** The gates of `docs/arquitetura.md` §6 stay with the coordinator.
  Scratch command 2 covers the two files this slice touched, not the project.
- **No txiki.js run.** Nothing in this slice was executed under `bin/tjs`. The module was written
  against APIs the runtime is already known to have: `crypto.subtle.digest` and Ed25519 `verify`
  (measured in the runtime by H3 and S0, `docs/tinyjs.md` §5), and the rest — `TextDecoder`,
  `setTimeout`, `Response` with `headers`/`body`/`arrayBuffer()` — is what `backend/probe-net.ts`
  uses under the same runtime plus one `leitura` of the runtime's own code:
  `~/.tinyjs/runtime/bridge.js:2651` buffers a fetch with `new Uint8Array(await res.arrayBuffer())`
  in the backend, which is why `readBody` uses `arrayBuffer()` instead of a reader loop. Base64url is
  `shared/encoding.ts`'s hand-written decoder, so the module touches no `atob`/`btoa`. Measured in
  txiki.js: nothing. Degrees, not measurements: `crypto.subtle` is `execucao` of two other slices,
  the rest is `leitura`.
- **No network capture of RF-30.** The construction is proven (test + `leitura`); the capture on the
  real surface belongs to the two-instance smoke of SP05 §5, B11.
- **`event.client_id`/`sent_at` land as columns only.** SP05 §2 says the client id is "filled on
  insert from now on"; `addEvent` still inserts with both columns `NULL`, because filling them means
  `AuditEvent` gains `clientId` in `shared/types.ts` and the push/ack has no caller until B10. A
  finding for the coordinator, not a decision of this slice.

## Findings and decisions for the coordinator

1. **`fingerprintOf` lives in `backend/host-client.ts` and belongs in `shared/host-api.ts`.** The
   host must compute the same string for `Discovery.fingerprint` (H6) and
   `shared/host-api.ts:407`'s `encodeBase32` is private, so two copies are free to drift. `shared/`
   was not this slice's to edit; moving the function there (exporting `encodeBase32` or a
   `fingerprintOf`) removes the copy in one commit.
2. **`Response.arrayBuffer()` is now load-bearing.** If txiki.js is ever found not to implement it on
   a buffered `Response`, the read must become probe-net's reader loop; the citation is in "What
   could not be done".
3. **`migrate()` completes `0`, `2` and `3` and refuses everything else.** `1` and `4`+ are refused
   with `unsupported database version: <n>` (the test covers both). `2` is now a *past* version: it
   is completed and re-stamped, never refused.
4. **`Repo.hostRecord()` answers `HostRecord`, which is not SP05 §3's `HostState`.** `HostState` is
   the RPC shape (guild, address, fingerprint, `lastSyncAt`, `lastError`, the pending count) and has
   no home in `shared/types.ts` yet; B2 owns it and can build it from this row plus
   `listOutbox().length`. Nothing of `HostState` was invented here.
5. **`saveHost` replaces the row whole and does not touch the outbox.** Replacing a guild is
   `clearHost()` first, then `saveHost`: dropping the pending writes is a decision about the person's
   data (`host.remove`'s `keepPersonal`, SP05 §3) and it is not this slice's to make.
6. **`minAppVersion` is shape-checked and not compared.** SP04 §1 puts a semver in the discovery and
   no story compares it yet; there is no semver helper in `shared/` to reuse. B2 should decide where
   the refusal lives.
7. **`401` is mapped and not acted on.** SP04 §3 clears the token, drops org data and asks for
   sign-in on a `401`; that is B10's (with `backend/sync.ts`), so `request`/`snapshot` only raise
   `HostError('signed-out', 'signed out')` and leave the token alone.
8. **The clock is injected and used for the one deadline.** `REQUEST_TIMEOUT_MS` (10 s, the same
   ceiling as `backend/probe-net.ts`) with `timeoutMs` as the knob a test tightens; the runtime's
   `fetch` takes no `AbortSignal` (`TinyFetchInit`), so the deadline is a timer racing the promise,
   as in the probe. If B4's backoff wants the clock, `deps.now` is already there.
9. **The client's own types live in `backend/host-client.ts`.** `HttpMethod`, `HostError`,
   `HostFailure`, `PinnedHost`, `HostDiscovery`, `SnapshotResult`: none of them is in `shared/` and
   none duplicates an exported name of `shared/host-api.ts` (`Discovery`, `Snapshot`,
   `SNAPSHOT_SIGNATURE_HEADER` are imported, not restated). If B4/B10 need `HostFailure` in
   `shared/`, it is a move, not a second definition.
10. **No new dependency, no toolchain change, no alias, no re-export.** `backend/host-client.ts`
    imports `shared/catalog.ts`, `shared/encoding.ts`, `shared/host-api.ts` and `shared/seal.ts`; the
    `If-None-Match` header name is the one local constant, because only the *answer* header of SP04 §2
    is in the contract.
