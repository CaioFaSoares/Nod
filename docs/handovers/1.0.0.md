## 2. Version sources (read this before bumping again)

- `app.json` `version` is the **release source of truth**: `release-branch.yml` reads it to name the
  branch `release-<version>`, `release.yml` reads it for the tag `release-<version>`, the artifacts
  and the release title (`docs/distribuicao.md` §8).
- `package.json` `version` mirrors it for tooling metadata; nothing in the release flow reads it.
- `Casks/nod.rb` is **written by CI after publishing** (`scripts/brew-cask.ts` in the `cask` job of
  `release.yml`, committed to `main`) — this release wrote it by hand through the same script, the
  billing-locked fallback of `docs/handovers/0.9.0-ui.md`.
- `electrobun.config.ts` is generated (gitignored) from `app.json` by
  `scripts/gen-electrobun-config.ts`; never edit it.

Bumped here: `app.json` and `package.json` to `1.0.0` (2026-11-19).

## 3. The gate, measured at the cut

`release.yml`'s `prepare` job runs `bun run typecheck:app` and `bun test test/`, so the branch must be
green first. The local pass, in this order:

1. `bun run typecheck` (app + backend + host). 2. `bun test test/` and `bun test host/`.
3. `bun run validate` and, on the real surface, `bun run validate --smoke`. 4. `bun run eb:build
&& bun run eb:verify` for the release bundles.

**Measured on 2026-11-19, before the cut (execution):**

- `bun run validate` **4/4** — typecheck (src, backend, host, electrobun), unit tests `test/`
  **1139 pass, 0 fail**, unit tests `host/` **205 pass, 0 fail** (the portal's 6 included), build
  (tsc + vite + the portal's vite).
- `bun run validate --smoke` — **run smoke: 14 steps ok**; **ui smoke: 8 stages, 7 launches, all
  checks ok**, the RF-79 library stage and the RF-72 style-toggle stage included; **connected
  smoke: exit 0, 15 phases, 124 steps**, the `person-second-guild` phase (9 steps: join B with A
  held, both tiles, enter A, enter B, remove B, A still enters) and the web-portal check (the page
  with its CSP, the derived-key cookie sign-in, the `web` device row, the granted catalog, the
  refused foreign origin, the revoked sign-out) among them; **tabs smoke: every functional check
  ok** — the popup nests under its opener, `tabs.move` reorders the family and refuses what is not
  the same parent's child, a parent's close takes its children — and the **five real-mouse stages
  blocked** (below).

## 4. The two caveats this release carries (owner-accepted)

1. **macOS Accessibility authorization is still off**, so the smoke's five real-mouse stages
   (`test/smoke/click.swift` preflights `CGPreflightPostEventAccess`) answer blocked and the tabs
   suite exits 1. This is the same caveat the owner accepted at 0.9.0
   (`docs/handovers/0.9.0-ui.md`): the stages' functional subjects are proven (the strip switches,
   the menu opens, the close-all closes — by the DOM paths the same checks drive), but the
   OS-level click delivery is not. On an authorized machine, run `bun run validate --smoke` once
   and require the five stages to answer ok.
2. **GitHub Actions stays locked by billing** ("your account is locked due to a billing issue"), so
   the six-target CI release did not run. The macOS arm64 and Intel bundles were built locally with
   the paired, verified toolchains (Hutch `macos-x64` under Rosetta; the Intel native helper with
   `--arch=x86_64`), both `eb:verify`- and `codesign --verify --strict --deep`-checked, both
   launcher- and payload-architecture-checked. **Windows/Linux 1.0.0 artifacts do not exist** —
   no six-target claim — and the release notes say so.

## 6. Follow-ups

- On an authorized macOS session, rerun `bun run validate --smoke`; the five blocked stages are the
  only answers that can change.
- When billing unlocks, dispatch `release.yml` on `release-1.0.0` for the Windows/Linux artifacts;
  until then the manifest carries the two Macs and the updater stays honest.
- The smoke runners (`test/smoke/*.ts`) are executed by Bun but not typechecked — the swapped-
  argument bug the connected smoke caught (`generatePage`'s `methods`/`addressB`) is that class's
  example. A `test/smoke/tsconfig.json` with Bun's types is the fix; it needs the backend's ambient
  declarations and pre-existing strictness, and it did not fit the cut.
- The web portal's browser-rendered half is proven by the routes, the build and the smoke's HTTP
  drives; a browser-automation pass (the page's own four views on a real engine) is the same
  follow-up shape the appearance harness had before the RF-72 stage landed.
