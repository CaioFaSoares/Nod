Pedido do dono em 2026-11-20: “atualize no git como 1.0.1” e, depois, “crie a release manualmente,
a action nao ta rodando por causa do billing”. Esta é a execução da publicação pelo caminho manual
de 0.9.0/1.0.0; o GitHub Actions não foi executado.

## 3. Release manual — execução em 2026-11-20

O GitHub Actions continua bloqueado por billing, como em 0.9.0 e 1.0.0. A publicação foi feita
manualmente, a partir de `main`, sem reutilizar artefatos de outra versão:

1. O bundle **arm64** foi construído localmente com o Electrobun 2.0.5 / Hutch 0.28.2 e o Bun 1.4.4.
2. O bundle **x86_64** foi construído com o Bun oficial `bun-darwin-x64` 1.4.4 sob Rosetta. O helper
   nativo foi compilado com `bun scripts/build-nod-native.ts --arch=x86_64`; o Hutch `macos-x64` foi
   resolvido pelo próprio runtime.
3. Os dois passaram por `bun run eb:verify`, por `codesign --verify --strict --deep` e por uma
   extração nova dos zips publicados. Launcher e `libNodNative.dylib` do payload são `arm64` no
   pacote Apple silicon e `x86_64` no Intel; a plist externa e a do payload dizem **1.0.1**.
4. Os zips foram gerados por [scripts/eb-publish.ts](../../scripts/eb-publish.ts), com
   `base-url` apontando para a pasta `latest/download`. As duas metades do manifesto foram unidas
   pelo mesmo `jq` do workflow; o parser do app aceitou o documento final.
5. Os assets do rascunho foram baixados de volta do GitHub e conferidos antes de publicar. Depois da
   publicação, os dois zips e o manifesto também foram baixados pela URL pública `latest` e os
   hashes coincidiram.
6. O [cask](../../Casks/nod.rb) foi regenerado a partir do manifesto publicado pelo
   [script do Homebrew](../../scripts/brew-cask.ts), sem hashes escritos à mão.

## 4. Validação sobre o commit publicado

```sh
bun run validate
bun run eb:verify
```

Resultado: **4/4 etapas**, código 0, **43,4 s**. Typecheck de app/backend/host/Electrobun;
**1.141 testes** de app/backend e **205 de host**, sem falhas; **7.147 asserções**; builds de produção
desktop e portal. `eb:verify` confirmou os dois bundles e os payloads.

Também foram checados: a igualdade das versões de `app.json`, `package.json` e da configuração
Electrobun gerada; o seed privado embutido nos dois bundles; e os hashes de todas as fontes e
artefatos do [manifesto visual](../evidence/ui-cleanup/manifest.json).

O smoke nativo e as fixtures visuais do [handover da limpeza](ui-cleanup.md) são as execuções
registradas antes do corte; não foram reexecutados só para a troca de versão. Nenhuma credencial real
foi usada nesta publicação.

## 5. Limitações e continuidade

- **macOS apenas.** A release carrega os dois Macs. Windows/Linux 1.0.1 não existem enquanto o
  GitHub Actions estiver bloqueado; não há claim de seis alvos. Quando o billing voltar, uma execução
  de `release.yml` pode produzir esses artefatos e completar o manifesto.
- **Assinatura ad hoc.** É a mesma condição das releases anteriores; o macOS exige a etapa de
  remoção de quarentena descrita na [distribuição](../distribuicao.md).
- **Sem nova aprovação de acessibilidade.** O smoke nativo anterior já registrava os limites de
  entrega de cliques do sistema; esta release não os transforma em verificação.
- Fora do Git permanecem a configuração local de agente, o diretório de prévias, o seed privado e as
  saídas de build. O commit desta publicação atualiza o cask e este registro.
