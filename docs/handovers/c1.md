## Decisions and deviations for the coordinator

1. **The code helpers landed in `shared/host-api.ts`, not in `shared/auth.ts`.** SP05 §1's module table
   and `shared/context.md`'s "Changes planned" table both put "access-code normalize/format" in
   `shared/auth.ts`, and the mandate put them in `shared/host-api.ts` with `shared/auth.ts` explicitly
   out of the file list. The assignment won. It is a divergence for the coordinator: amend the two
   tables, or move the helpers later — the call sites are H4's routes and the `setup-code` command, all
   unwritten, so the move is cheap today and expensive after H4 lands. `normalizeEmail` is in the same
   position (`host/repo.ts` and `backend/repo.ts` each carry their own `trim().toLowerCase()`, and
   neither imports it).
2. **`Entry.scope` is `'org' | 'personal'`, and nothing else was added.** `docs/canonico.md` §17 gives
   the *local catalog* an `origem` (`local` vs `host:<id>`) and a `versao`, but SP04 §2 (the change
   that lands `Entry.scope/ownerId`) and SP05 §2 (which adds only `scope` and `owner_id` to the local
   `tool` table) define no such field, so no `origin`/`source`/`version` was invented here. If the
   catalog source is needed on the Bond side, it is a spec line first.
3. **`AdminPerson` is `Person` + `kind`/`activatedAt`/`disabledAt`** — exactly the columns
   `host/repo.ts`'s `HostPerson` adds — and never `salt`/`auth_hash`, so `GET /v1/admin/people` can
   return the repo's rows directly (H2 decision 2).
4. **`DeviceSession` omits `revokedAt`**: SP03 §2 lists "the caller's sessions", and
   `repo.sessionsOfPerson` answers live sessions only. A `SessionRecord` is assignable to it either
   way (an extra property never blocks an assignment).
5. **`ClientEvent.kind` is `EventType`; `HostEvent.kind` is `string`.** The Bond only sends kinds it
   can produce, so the batch is closed by construction; the admin list shows what the host holds, which
   a newer host may have extended. Finding: SP04 §4 raises `sync.rejected`, which is **not** in
   `EventType` (`shared/types.ts`) — if B10 pushes that kind, `EventType` gains the member, one line
   this slice did not take because the field additions to `shared/types.ts` were scoped to
   `Entry`/`View`.
6. **`BootstrapResponse` is `{ created: number }`.** SP03 §2 writes the answer as `{ created }` and
   types nothing; the number of org tools created is the most literal reading, and `repo.bootstrap`
   answers `void`, so the route counts what it wrote. **Finding:** if B8a needs the ids (or a pair of
   counts), decide it before H5 implements the route — the change is one line here plus the route.
7. **`SnapshotEnvelope` carries the parsed half of the two headers** (`version` for the `ETag`, and
   `{ kid, sig }` for `Bond-Signature`), with `SNAPSHOT_ETAG_HEADER` and `SNAPSHOT_SIGNATURE_HEADER` as
   the names. No format/parse helper was added: SP04 §2's exact header syntax stays with its two
   writers (H6 host-side, B1 Bond-side), and the mandate's helper list did not include one.
8. **`generateCode(kind)` answers the formatted code** (`XXXX-XXXX`), and the kinds are named
   `access`/`setup` while the host's stored purpose for the first is `activate`
   (`host/repo.ts`'s `CodePurpose`, SP01 §2). Documented on `CodeKind`; the mapping is H4's, and the
   compiler catches a mix-up at the call site.
9. **`PersonalTool extends Entry`** (so `roles`/`views` travel, with `roles: []` for a personal tool,
   which is what SP04 §2's `personalTools: Entry[]` prescribes), and **`PersonalView = View & { id;
   entryId; updatedAt }`** — an intersection, because `View.id` is optional for the local catalog and
   required here. The host's `EntryInput`/`PersonalViewInput`/`HostTool` rows are assignable.
10. **`DeleteRequest`, `FavoritesRequest` and `AdminEventsQuery` are named after the routes**, not
    after the repo's `updatedAt`/`HostEventFilter` row types, because the wire names of the query are
    `person`, `tool`, `from`, `to`, `limit` and the repo's are `personId`, `toolId`.
11. **`HOST_ROUTES` holds the 26 block 1 paths**, `:id` included and documented; block 2 paths are not
    there. `HOST_ROUTES.health` is the only text answer of SP03 §2.
12. **No new dependency, no toolchain change, no alias, no re-export, no second name for an existing
    type.** `shared/host-api.ts` imports only `./types` and only as types; `shared/encoding.ts` imports
    nothing.
